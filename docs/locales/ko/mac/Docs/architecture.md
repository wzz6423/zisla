# 아키텍처와 성능 설계

[English](../../../../../mac/Docs/architecture.md) | [简体中文](../../../../../mac/Docs/architecture.zh-CN.md) | **한국어** | [다른 언어](../../../README.md)

## 상단 진입 감지

숨겨진 상태에는 투명 창이 없습니다. `PointerEdgeMonitor`는 마우스 이동·드래그에 전역 및 로컬 `NSEvent` 감시를 등록합니다. `ScreenLayoutEngine`은 좌표 계산만으로 각 화면 상단 중앙 6 px 영역에 들어왔는지 판단합니다.

`NSScreenNumber`와 해당 `CGDirectDisplayID`를 연결해 안정적인 화면 ID를 만듭니다. 배치는 `screen.frame.maxY`를 기준으로 하므로 음수 좌표, 수직 배치와 노치 없는 외부 화면을 지원합니다.

여러 디스플레이를 연결하면 설정 → 일반 → 디스플레이 모드에서 화면마다 Dynamic Island 모드(카메라 또는 사용자 위치), 노치 모드, 숨기기를 선택할 수 있습니다. 화면이 하나면 이 설정을 숨기고 전체 외관 설정을 사용하며, 다시 연결하면 각 화면의 저장된 설정을 복원합니다. 표시가 활성화된 모든 화면에 접힌 아일랜드가 동시에 표시됩니다. 펼치기, 빠른 작업, 녹음, 임시 메시지는 해당 화면의 아일랜드만 대체합니다. 알림 표시 화면을 선택해도 대기 중인 아일랜드는 숨겨지지 않습니다.

## 창

주 아일랜드는 하나의 `.borderless + .nonactivatingPanel`입니다.

- `.statusBar` 수준을 사용하며 시스템 잠금 화면이나 메뉴를 덮지 않습니다.
- `.canJoinAllSpaces + .fullScreenAuxiliary`로 Spaces와 일반 전체 화면 앱을 지원합니다.
- 포인터를 올려 펼칠 때 `NSApp.activate`를 호출하지 않아 현재 앱의 포커스를 유지합니다.
- 숨길 때 `orderOut`을 사용하므로 투명 창이 메뉴 막대 영역을 차지하지 않습니다.

좌우 알림 패널은 필요할 때 만들고 큐가 비면 숨깁니다.

## 상태와 동시성

- AppKit, SwiftUI 상태와 창 제어는 `MainActor`에 둡니다.
- 다운로드, 날씨와 GitHub 요청에는 actor를 사용합니다.
- hook이 쓴 AI 상태는 디렉토리 파일 이벤트로 감시합니다. 각 AI 세션 원본은 최신 로컬 세션·활동 파일의 수정 시각과 크기를 비교하고 변경이 없으면 파싱 캐시를 재사용합니다.
- 필요한 구조화 이벤트, 고정 상태, 메타데이터만 읽고 프롬프트와 답변은 읽지 않습니다. 한 제공자 오류는 다른 제공자를 막지 않습니다.
- AI 계정 한도는 제공자별로 조회한 값입니다. Antigravity의 Gemini와 Claude/GPT는 재설정 기간과 한도 부족 알림을 각각 유지합니다. Gemini App의 일반 대화 한도는 같은 Google 계정의 저장된 웹 Cookie로 조회하고 Gemini CLI는 로컬 OAuth를 사용합니다. 없는 한도를 추정하지 않습니다.
- 접기 지연에는 취소 가능한 `Task`와 세대 토큰을 사용해 이전 작업이 다시 열린 아일랜드를 숨기지 않게 합니다.
- 숨긴 상태에서는 `TimelineView`, 60 Hz 타이머 또는 지속적 애니메이션 제출을 사용하지 않습니다.

## 미디어 감지

MediaRemote로 제목·표지·진행·제어를 얻습니다. Core Audio 14.4+ 프로세스 속성으로 활성 오디오 출력과 정보가 없을 때의 소스 앱을 확인합니다. 속성 리스너와 제한된 주기적 확인으로 목록과 상태를 갱신하며 오디오 수집, 화면 기록·손쉬운 사용 권한 요청이 없습니다. 일시정지·정지·음소거 소스는 표시에서 제외합니다.

## 녹화와 앱 믹서

녹화와 믹서는 메타데이터 감지와 별도입니다. 화면 기록과 켜진 마이크·카메라 권한을 요청해 선택한 미디어를 로컬에 저장하고 녹화 폴더에서 프로젝트를 관리합니다. 믹서는 macOS 14.4+ Core Audio tap과 시스템 오디오 기록 권한을 사용합니다.

## 소재

macOS 26은 한 층의 SwiftUI `glassEffect`를 사용하며 macOS 14/15는 한 층의 `NSVisualEffectView`를 사용합니다. 투명도 감소 설정을 켜면 불투명 배경으로 바뀝니다. 여러 흐림 효과나 재질을 겹치지 않습니다.

## 다운로드 안전 경계

Swift는 `Process.executableURL`과 인수 배열로 `yt-dlp`를 실행합니다. URL은 항상 `--` 뒤의 별도 argv 값입니다. 런타임 설정, 플러그인과 exec를 끄고 출력 파이프를 동시에 비우며 JSON 표식으로 진행을 읽습니다.

종료 0, 파일 존재, 심볼릭 링크 해석 후 허용 폴더 내부를 모두 만족해야 성공입니다. 각 작업은 자신의 UUID 임시 폴더만 지웁니다.

## 업데이트 확인과 다운로드

선택 채널은 실행마다 한 번 공개 출구 국가를 얻고 Sparkle이 설치된 빌드의 서명된 appcast를 읽습니다. HTTPS ZIP을 받아 압축 해제 전에 EdDSA 아카이브와 feed 서명을 검사한 뒤 교체·재실행합니다. `CN`은 Gitee(Release의 `update-release`, Preview의 `preview`)를 먼저 사용한 뒤 GitHub를 한 번 재시도합니다. 다른 국가는 반대, 국가 실패는 Gitee 우선입니다. 각 feed는 같은 호스트 ZIP을 가리킵니다.

릴리스는 공통 `appcast.xml` 옆에 아키텍처별 appcast를 게시합니다. 단일 아키텍처는 자신의 slice feed를 요청하며 번역 실행된 x86_64는 arm64를 요청해 Universal로 바뀌지 않습니다. Universal은 자체 slice 수로 판단하여 `appcast.xml`을 유지하며 이전 공통 업데이트 버전도 이 이름을 사용합니다. 설정 변경은 자동·수동 확인과 Sparkle 다음 주기를 초기화합니다. 공개키는 계정 정보가 없고 개인키는 관리자의 Keychain 또는 보호 파일에 있습니다.
