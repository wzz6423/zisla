# Архитектура и проектирование производительности

[English](../../../../../mac/Docs/architecture.md) | [简体中文](../../../../../mac/Docs/architecture.zh-CN.md) | **Русский** | [Другие языки](../../../README.md)

## Активация у верхнего края

В скрытом состоянии нет прозрачного окна. `PointerEdgeMonitor` устанавливает глобальные и локальные наблюдатели `NSEvent` для перемещения мыши и перетаскивания; `ScreenLayoutEngine` определяет вход указателя в верхнюю центральную область 6 px каждого дисплея только геометрией.

Каждый дисплей получает устойчивую идентичность из пары `NSScreenNumber` и `CGDirectDisplayID`. Макет привязан к `screen.frame.maxY`, поэтому поддерживаются отрицательные координаты, вертикально расположенные дисплеи и внешние экраны без выреза.

При подключении нескольких экранов в Настройки → Основные → Режимы экранов можно выбрать для каждого режим Dynamic Island (положение камеры или своё положение), режим выреза или скрытие. С одним экраном настройка скрыта и применяется общий вид; повторное подключение восстанавливает сохранённую конфигурацию каждого экрана. На всех видимых экранах свёрнутый островок отображается одновременно. Разворачивание, быстрые действия, запись и временные сообщения заменяют островок только на своём экране; выбор экранов для уведомлений фильтрует содержимое, не скрывая неактивный островок.

## Окно

Основной остров сохраняет единственную панель `.borderless + .nonactivatingPanel`:

- Использует уровень `.statusBar` и не покрывает системный экран блокировки или системное меню.
- `.canJoinAllSpaces + .fullScreenAuxiliary` поддерживает Spaces и обычные полноэкранные приложения.
- Раскрытие при наведении не вызывает `NSApp.activate` и не перехватывает фокус.
- Скрытие использует `orderOut`, поэтому прозрачное окно не занимает область строки меню.

Левая и правая панели уведомлений создаются по запросу и скрываются сразу после опустошения очередей.

## Состояние и конкурентность

- AppKit, состояние SwiftUI и управление окнами остаются на `MainActor`.
- При включении управления строкой меню zisla создаёт два элемента `NSStatusItem`. Пока список значков открыт, приложение читает `AXExtrasMenuBar` и проверяет положение выбранного значка после перемещения.
- Загрузки, погода и запросы GitHub используют actors.
- Записанное хуками состояние AI отслеживается через события файловой системы каталога. Каждый источник сеансов сравнивает последний локальный файл сеанса/активности по mtime и размеру, повторно используя кэш разбора при отсутствии изменений.
- Автоматическое обнаружение читает только структурированные события, фиксированные маркеры состояния и нужные метаданные активности. Тексты запросов/ответов не читаются; ошибка анализатора провайдера не блокирует остальных.
- Квоты аккаунтов AI запрашиваются отдельно у каждого провайдера. Квоты Gemini и Claude/GPT в Antigravity сохраняют собственные окна сброса и уведомления. Квота обычного чата Gemini App использует сохранённый веб-Cookie того же аккаунта Google; Gemini CLI сохраняет локальный OAuth. Отсутствующие квоты не оцениваются.
- Задержки сворачивания используют отменяемые `Task` и токен поколения, чтобы старая задача не скрыла вновь открывшийся остров.
- Скрытое состояние не содержит `TimelineView`, таймера 60 Hz или постоянной отправки анимации.

## Обнаружение медиа

MediaRemote предоставляет название, обложку, прогресс и управление. Свойства объектов процессов Core Audio 14.4+ подтверждают активный поток вывода и дают резервное приложение-источник при отсутствии метаданных. Списки процессов и состояние выхода управляются слушателями свойств с ограниченной периодической проверкой; содержимое аудио не захватывается, разрешения записи экрана или Accessibility не запрашиваются. Приостановленные, остановленные и заглушённые источники не остаются в медиаобласти.

## Запись и микшер приложений

Запись экрана и микшер громкости отделены от обнаружения метаданных. Запись запрашивает запись экрана и разрешения включённых микрофона/камеры, хранит выбранное медиа локально и проекты в выбранной папке записей. Микшер использует taps Core Audio на macOS 14.4+ и требует разрешения записи системного звука.

## Материалы

macOS 26 использует однослойный SwiftUI `glassEffect`; macOS 14/15 — однослойный `NSVisualEffectView`. Reduce Transparency переключает фон на непрозрачный. Остров не складывает несколько слоёв размытия или материала.

## Граница безопасности загрузок

Swift запускает `yt-dlp` через `Process.executableURL` и массив аргументов; URL всегда отдельное значение argv после `--`. Конфигурация выполнения, плагины и exec отключены, выходные каналы читаются параллельно, прогресс разбирается по сигнальной метке JSON.

Задача успешна только при коде завершения 0, существующем выходном пути и нахождении разрешённого пути внутри авторизованного каталога. Каждая задача очищает только собственный временный каталог с именем UUID.

## Проверки и загрузки обновлений

Выбранный канал один раз за запуск определяет страну публичного выхода, затем Sparkle получает подписанный appcast установленной сборки, скачивает указанный ZIP по HTTPS, проверяет подписи EdDSA архива и ленты до извлечения, заменяет приложение и перезапускает его. `CN` начинает с Gitee (`update-release` для Release, `preview` для Preview) и один раз повторяет соответствующую ленту GitHub; другие страны начинают с GitHub и один раз повторяют Gitee. Недоступное определение сохраняет Gitee первым; каждая лента указывает подписанный ZIP своего хоста. Выпуск публикует appcast каждой архитектуры рядом с общим `appcast.xml`; одноархитектурная установка запрашивает свою архитектуру (транслируемый x86_64 запрашивает `arm64`) и не заменяется универсальной сборкой. Универсальная установка считает архитектуры собственного исполняемого файла и остаётся на `appcast.xml`, также обслуживающем старые выпуски. Изменение настройки влияет на автоматические/ручные проверки и сбрасывает следующий цикл Sparkle. Встроенный открытый ключ не содержит учётных данных; закрытый ключ остаётся в macOS Keychain сопровождающего выпуск или отдельно защищённом файле.
