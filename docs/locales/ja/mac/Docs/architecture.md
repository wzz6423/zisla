# アーキテクチャと性能設計

## 上端での起動

非表示状態では透明ウィンドウがありません。`PointerEdgeMonitor` はマウス移動とドラッグをグローバル・ローカル `NSEvent` で監視し、`ScreenLayoutEngine` が画面ごとの上部中央 6 px に入ったかを幾何計算します。

各画面は `NSScreenNumber` と `CGDirectDisplayID` で安定した識別子を持ちます。`screen.frame.maxY` を基準にし、負座標、上下配置、ノッチなし外接画面に対応します。

複数のディスプレイを接続すると、設定 → 一般 → ディスプレイのモードで、各画面に Dynamic Island モード（カメラ位置または独自位置）、ノッチモード、非表示を選べます。1 画面ではこの設定を隠して全体の外観を使い、再接続すると画面ごとの設定を復元します。表示対象の各画面には、折りたたまれたアイランドが同時に表示されます。展開、クイックアクション、録音、一時メッセージは、その画面のアイランドだけを置き換えます。通知先の画面を選んでも、待機中のアイランドは非表示になりません。

## ウィンドウ

メインアイランドは一つの `.borderless + .nonactivatingPanel` を使います。

- `.statusBar` レベルで、システムのロック画面やメニューを覆いません。
- `.canJoinAllSpaces + .fullScreenAuxiliary` により Spaces と通常の全画面に対応します。
- ホバー展開は `NSApp.activate` を呼ばず、現在のアプリのフォーカスを維持します。
- 非表示は `orderOut` を使い、透明ウィンドウがメニューバー領域を占有しません。

左右の通知パネルは必要なときに作り、キューが空になると隠します。

## 状態と並行処理

- AppKit、SwiftUI の状態とウィンドウ制御は `MainActor` に置きます。
- メニューバー管理を有効にすると、zisla は 2 つの `NSStatusItem` を作成します。アイコン一覧を開いている間は `AXExtrasMenuBar` を読み、移動後に選択したアイコンの位置を確認します。
- ダウンロード、天気、GitHub の通信は actor を使います。
- hook の AI 状態はディレクトリーのファイルシステムイベントで監視します。各 AI セッションの検出元は最新のローカル会話・活動ファイルの mtime とサイズを比較し、変わらなければ解析キャッシュを再利用します。
- 自動検出は判断に必要な構造化イベント、固定状態マーカー、活動メタデータだけを読み、プロンプトや回答本文を読みません。一つの Provider の失敗は他を止めません。
- AI アカウントの割当はプロバイダーから個別に取得します。Antigravity の Gemini と Claude/GPT はリセット期間と低残量通知を分けます。Gemini App の通常チャットの割当は同じ Google アカウントの保存済みウェブ Cookie で取得し、Gemini CLI はローカル OAuth を使います。欠けた割当は推定しません。
- 折りたたみ待機はキャンセル可能な `Task` と世代 token を使い、古い処理が開き直したアイランドを隠さないようにします。
- 非表示状態には `TimelineView`、60 Hz タイマー、継続するアニメーション処理がありません。

## メディア検出

MediaRemote はタイトル、画像、進行と操作を提供します。Core Audio 14.4+ のプロセス属性で活動中の出力を確認し、メタデータがないときは音源アプリを表示します。リストと状態は属性リスナーと範囲を限定した定期確認で更新し、音声内容を収録せず、画面収録やアクセシビリティ権限を要求しません。停止、一時停止、ミュートされた音源は表示に残りません。

## 録画とアプリ音量ミキサー

録画とミキサーはメタデータ検出とは別の経路です。録画は画面収録と有効にしたマイク・カメラの権限を要求し、選択したメディアをローカル保存し、録画フォルダーにプロジェクトを管理します。ミキサーは macOS 14.4+ の Core Audio tap を使い、システム音声収録権限が必要です。

## 素材

macOS 26 は単層の SwiftUI `glassEffect`、macOS 14/15 は単層の `NSVisualEffectView` を使います。透明度を下げる設定では不透明背景になります。複数のぼかし・素材を重ねません。

## ダウンロードの安全境界

Swift は `Process.executableURL` と引数配列で `yt-dlp` を起動し、URL は常に `--` の後の独立した argv です。設定ファイル、プラグインと exec は無効、出力パイプは並行して読み取り、JSON sentinel で進行を解析します。

終了コード 0、出力先の存在、シンボリックリンク解決後も許可ディレクトリー内という条件をすべて満たしたときに成功します。各タスクは自分の UUID 一時ディレクトリーだけを清掃します。

## 更新の確認とダウンロード

選択した更新チャンネルは実行ごとに公開出口の国コードを一度取得し、Sparkle がそのインストールに対応する署名済み appcast を読みます。HTTPS で ZIP を取得し、展開前に EdDSA のアーカイブと feed の署名を検証して置き換え、再起動します。`CN` は Gitee（Release は `update-release`、Preview は `preview`）を先に読み、GitHub を一度再試行します。他の国は GitHub、次に Gitee、国コード未取得は Gitee 優先です。各 feed は同じホストの署名済み ZIP を参照します。

リリースは共有 `appcast.xml` と各アーキテクチャの appcast を持ちます。単一アーキテクチャは自分の slice の feed（変換実行中の x86_64 は `arm64`）を要求し、Universal に置き換わりません。Universal は自身の slice 数を確認して `appcast.xml` を使い、これはアーキテクチャ別更新導入前の版にも対応します。チャンネル変更は自動・手動確認と次回の Sparkle 周期をリセットします。公開鍵にアカウント情報はなく、秘密鍵は管理者の macOS Keychain または保護されたファイルに置きます。
