# v0.1.0 Preview 发版记录

## 已验证的发布结果

- GitHub `v0.1.0` 是 prerelease；Gitee 也有同 tag 的 Preview Release。
- 两端都包含 universal DMG、universal ZIP 和 ZIP 的 SHA-256；Gitee 另外自动生成源码 ZIP 与 TAR，不是遗漏附件。
- App 的 `CFBundleVersion` 是 `1`，使用 ad-hoc 签名。后续版本应保持递增，便于人工识别构建顺序。
- 最终应用主程序包含 `arm64`、`x86_64`。早期临时目录中的单架构包不是发布物，不能再次上传。

## 以后必须保持的顺序

1. 先完成所有构建、签名、公证（如有）和归档生成。
2. 上传 ZIP、DMG 和 SHA-256；更新时至少应同步替换 DMG。
3. 下载远端 DMG 并核对 SHA-256 与本地最终产物。
4. Gitee 单独创建或更新同 tag Release 并上传同一批附件；GitHub 镜像不会同步 Release 附件。

## v0.1.0 后的版本策略

Preview 和 Release 共用全局构建号。示例：

```text
v0.1.1-preview.1  -> 2
v0.1.1-preview.2  -> 3
v0.1.1             -> 4
```

本记录描述的是 Sparkle 接入前的 Preview 发布，不得将其“只下载 DMG”的策略套用到后续版本。现在 Release 与 Preview 都通过独立的签名 appcast 和 Universal ZIP 自动更新；每次检查先读取 Gitee，检查或更新包下载失败时只回退 GitHub 一次。Preview 使用两端永久 `preview` tag 承载当前 appcast，正式 Gitee feed 使用永久 `update-release`。以主技能和 `update-channels.md` 为准。
